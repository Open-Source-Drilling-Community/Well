# ModelSharedOut

`ModelSharedOut` merges the Well OpenAPI document with checked-in dependency schemas, then generates the typed C# API clients used by `WebPages`, `WebApp`, and `ServiceTest`.

## Inputs

The generator reads every JSON file in `ModelSharedOut/json-schemas`:

| File | Source |
| --- | --- |
| `WellFullName.json` | Generated by a Debug build of `Service`. |
| `ClusterModel.json` | Cluster service-owned schema from `Cluster/ModelSharedOut/json-schemas/ClusterFullName.json`. |
| `FieldModel.json` | Field service-owned schema from `Field/ModelSharedOut/json-schemas/FieldFullName.json`. |
| `RigModel.json` | Rig service-owned schema from `Rig/ModelSharedOut/json-schemas/RigFullName.json`. |
| `VerticalDatumModel.json` | Earth Vertical Datum merged service schema. |
| `TrajectoryModel.json` | Trajectory service-owned schema from `Trajectory/ModelSharedOut/json-schemas/TrajectoryFullName.json`; the served transitive aggregate is intentionally not used. |
| `WellBoreModel.json` | WellBore service-owned schema from `WellBore/ModelSharedOut/json-schemas/WellBoreFullName.json`. |

Dependency files are deliberately checked in. Refresh them from reviewed, service-owned `*FullName.json` artifacts rather than served merged aggregates, which may contain stale transitive copies of other services.

Files are processed deterministically by name. For duplicate routes, dependency documents retain their first-known contract, while `WellFullName.json` is authoritative for routes owned by the current Well service. This prevents stale Well routes embedded in downstream merged schemas from replacing the current REST contract.

Generated query timestamps use the round-trip (`O`) format so optimistic-concurrency tokens retain their offset and sub-second precision.

## Outputs

- `ModelSharedOut/WellMergedModel.cs`: generated DTOs and API clients in `OSDC.Drilling.Well.ModelShared`.
- `Service/wwwroot/json-schema/WellMergedModel.json`: merged OpenAPI document served by the Well service.
- `ModelSharedOut/json-schemas/WellFullName.json`: refreshed by the Service Debug-build target.

Do not hand-edit generated outputs. Commit the input schema, C# client, and merged document changes together.

## Regeneration workflow

Run from the solution root:

```powershell
dotnet build Service\Service.csproj --configuration Debug
dotnet run --project ModelSharedOut
```

The generator asks before overwriting existing outputs; enter `Y`. It discovers the repository root by locating `Well.sln`, so run it from within the repository.

Then verify:

```powershell
dotnet build Well.sln
dotnet test ServiceTest\ServiceTest.csproj --filter "FullyQualifiedName!~McpServerHttpTests"
git diff --check
```

Regenerate whenever REST routes or request/response models change. Pure MCP schema changes do not alter the OpenAPI-generated client because MCP tools are registered outside the REST controller surface.
